# 🏘️ 재건축 동네분석

엑셀로 수작업하던 행정동 단위 재건축 분석을 **폰/PC 브라우저에서 바로 쓰는 앱**으로 옮긴 것.
서버·DB·로그인 없이 HTML 파일 하나로 동작한다.

## 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 앱 본체 (입력 + 자동계산 + 점수 + 비교표). 이 파일 하나면 끝 |
| `fetch_data.py` | 공공데이터포털 API로 실거래가·전세가율·점포수 자동 조회 |
| `targets.json` | 자동 조회 대상 동네 목록 (동 이름·시군구코드·단지명) |
| `output/auto.json` | 자동 조회 결과 — GitHub Actions가 매월 갱신, 앱이 자동 로드 |
| `../.github/workflows/dongne-auto.yml` | 매월 자동 실행 스케줄 |
| `../.github/workflows/dongne-pages.yml` | GitHub Pages 자동 배포 (빌드 시 config.js에 API 키 주입) |
| `manifest.webmanifest` | 폰 홈 화면에 "앱처럼" 추가할 때 쓰는 설정 |
| `config.template.js` / `config.js` | 배포 빌드가 API 키를 채워 넣는 자리표시자 (git에는 빈 값만) |
| `sw.js` | 서비스 워커 — 오프라인 캐싱, PWA 설치 활성화 |

## 기능

- 엑셀 항목 그대로: 인구/20~40대, 역 승하차, 상권 점포수, 신축·해당동·재건축 최고가,
  전세가율, 향후 입주, 용적률, 추진단계
- **동네 추가 화면에서 시/도 → 시/군/구 → 읍/면/동을 토글로 선택** (오타 방지, 법정동코드 자동 확보)
- **🔄 정보 불러오기 버튼** — 클릭하는 자리에서 바로 공공데이터포털 실거래·전세·상가 API를
  호출해 매매 최고가/평당가·전세가율·상권 점포수를 실시간으로 채운다 (채워진 항목은 파란색으로 잠깐 표시)
- **자동 계산**: 20~40대 비율, 전세가율, 가격 갭(신축 vs 재건축 평당가)
- **종합점수(100점) + 등급(S~D)**: 산정 기준은 앱의 [가이드] 탭 참고
- **동네 비교표**: 등록한 동네를 항목별로 나란히 비교, 최고값 하이라이트
- 데이터는 브라우저에 저장(localStorage), **JSON 내보내기/가져오기**로 폰↔PC 이동
- 다크모드, 모바일 우선 반응형, 본오동 예시 데이터 내장
- 매월 GitHub Actions로 전체 동네 일괄 자동 갱신도 별도로 계속 동작 (아래 "2단계" 참고)

### 정보 불러오기 버튼은 API 키를 브라우저에 노출합니다

"정보 불러오기"는 서버 없이 정적 페이지에서 바로 공공데이터 API를 호출하기 위해
**배포 시 `DATA_GO_KR_KEY`를 `config.js`에 그대로 심어서 배포**합니다 (`.github/workflows/dongne-pages.yml`이
빌드할 때만 주입 — git 저장소 자체에는 키가 남지 않음). 즉:

- 배포된 사이트를 여는 누구나 브라우저 개발자도구(F12) → Network/Sources에서 이 키를 볼 수 있습니다.
- data.go.kr 공공 오픈API는 **무료·과금 없음** — 최악의 경우도 계정의 일일 조회 한도(기본 10,000건)를
  다른 사람이 써서 그날 소진시키는 정도이며, 이때는 새 키를 발급받아 GitHub Secrets만 갱신하면 됩니다.
- 매달 자동 갱신되는 배치 파이프라인(`dongne-auto.yml`)은 이 키를 서버(Actions) 안에서만 쓰므로
  그쪽은 노출되지 않습니다 — 노출 위험은 오직 "정보 불러오기" 버튼 경로에만 해당합니다.

## 사용법

### 웹 배포 (다른 사람도 URL로 바로 사용)

`.github/workflows/dongne-pages.yml`이 `dongne/` 폴더를 GitHub Pages로 자동 배포한다.
저장소 소유자가 **한 번만** 설정하면 이후 `dongne/` 변경분은 push할 때마다 자동 반영된다.

1. GitHub 저장소 **Settings → Pages → Build and deployment → Source**를
   **"GitHub Actions"** 로 선택 (최초 1회)
2. **Actions** 탭 → "동네분석 앱 배포 (GitHub Pages)" → **Run workflow** 로 최초 1회 수동 실행
   (이후에는 `dongne/` 폴더가 바뀔 때마다 자동 실행)
3. 완료되면 `https://<계정명>.github.io/<저장소명>/` 에서 접속 가능
   (예: `https://land3lab.github.io/mrhomesga/`)

### 폰/PC에 "앱처럼" 설치

배포된 URL에 접속한 뒤:

| 기기 | 방법 |
|---|---|
| **Android (Chrome)** | 주소창 옆 ⋮ 메뉴 → "앱 설치" 또는 자동으로 뜨는 설치 배너 |
| **iPhone (Safari)** | 공유 버튼(⬆️) → "홈 화면에 추가" |
| **PC (Chrome/Edge)** | 주소창 오른쪽 설치 아이콘(⊕) 클릭 → "설치" |

설치하면 홈 화면/시작 메뉴에 아이콘이 생기고, 브라우저 주소창 없이 독립된 앱처럼 열린다.
`sw.js`(서비스 워커)가 화면 구성을 캐싱해두므로 오프라인에서도 이미 열어본 내용은 그대로 뜬다
(공공데이터 자동 갱신 값은 온라인일 때만 새로 받아온다).

### 그 외 방법

- **파일로 열기** — `index.html`을 더블클릭 (PC), 폰에는 파일을 보내서 브라우저로 열기.
  단, 이 경우 `sw.js` 설치 배너는 뜨지 않고 파일마다 새로 열어야 한다.

> 데이터는 **기기(브라우저)별로 따로 저장**된다. 폰과 PC에서 같이 쓰려면
> [가이드] 탭의 내보내기 → 파일 전송 → 가져오기를 이용.

## 앱 안에서 실시간 조회 (정보 불러오기 버튼)

배치 파이프라인(아래 2단계)과 별개로, 배포된 앱 화면에서 바로 실시간 조회도 가능하다.
아래 두 API도 (data.go.kr에서 같은 계정으로) 활용신청해야 [정보 불러오기]가 인구·역 승하차까지 채운다:
- 행정안전부_행정동별(통반단위) 성/연령별 주민등록 인구수
- 서울교통공사_역별승하차인원

1. 오른쪽 아래 **＋** 로 동네 추가 화면 진입
2. **시/도 → 시/군/구 → 읍/면/동**을 순서대로 토글 선택 (법정동코드를 몰라도 됨,
   선택하는 즉시 행정표준코드_법정동코드 API로 내부적으로 lawd를 확보)
3. 신축/해당 동/재건축 단지명, 인접역 이름은 **필수 입력** — 이 이름으로 검색하기 때문에
   비워두면 [정보 불러오기]가 아무것도 못 찾는다 (placeholder의 "예: OO" 텍스트는 실제 값이 아니니 주의)
4. **🔄 정보 불러오기** 클릭 → 매매·전세·상권·인구·(서울 지하철이면) 역 승하차 API를
   그 자리에서 호출해 값을 채움 (채워지는 항목이 파란색으로 잠깐 반짝임, 못 찾은 항목은
   완료 메시지에 사유가 표시됨)
5. 필요하면 값을 직접 수정한 뒤 **저장**

## 2단계: 자동 갱신 파이프라인

공공데이터포털 인증키 **하나**로 실거래 최고가·평당가 / 전세가율 / 상권 점포수를 자동 조회하고,
**GitHub Actions가 매월 자동 실행**해서 결과를 커밋한다. 웹으로 배포된 앱은 접속할 때
`output/auto.json`을 읽어 자동 반영한다 (수동 입력값은 보존, 자동 항목만 갱신).

```
targets.json (분석 대상 등록)
    ↓  매월 2일 06시 KST — .github/workflows/dongne-auto.yml
fetch_data.py → 국토부 실거래 API ×2 + 소상공인 상가 API
    ↓
dongne/output/auto.json 커밋
    ↓
앱 접속 시 자동 병합 (배포본) / [가져오기]로 수동 병합 (로컬 파일)
```

### 설정 (한 번만)

1. [data.go.kr](https://www.data.go.kr) 무료 가입 후 4개 API 활용신청 (즉시 자동 승인)
   - 행정안전부_행정표준코드_법정동코드
   - 국토교통부_아파트 매매 실거래가 상세 자료
   - 국토교통부_아파트 전월세 실거래가 자료
   - 소상공인시장진흥공단_상가(상권)정보
2. GitHub 리포지토리 **Settings → Secrets and variables → Actions**에
   `DATA_GO_KR_KEY` = 발급받은 인증키 등록
3. 분석할 동네를 `dongne/targets.json`에 추가 — **lawd(법정동코드)는 몰라도 된다**,
   umd 이름으로 자동 조회한다:

```json
{
  "name": "본오동",          // 앱에 표시될 동 이름
  "umd": "본오동",           // 법정동 이름 — 이 이름으로 법정동코드 자동 조회 + 실거래 필터
  "sigungu": "안산시 상록구", // 동 이름이 여러 지역에 있을 때만 필요한 힌트 (보통 생략 가능)
  "adongPrefix": "본오",     // 행정동 접두어 (본오1·2·3동 점포 합산, 코드 불필요)
  "apts": {
    "new": "그랑시티자이",   // 신축 대표 단지 (시군구 전체에서 검색)
    "dong": "우성",          // 해당동 최고가 단지
    "rebuild": "월드"        // 재건축 대상 단지
  }
}
```

동 이름이 전국에서 유일하면 `sigungu` 없이도 자동으로 찾는다. 같은 이름이 여러 시군구에 있으면
fetch_data.py가 후보 목록과 함께 에러를 내므로, 그때만 `sigungu`를 추가하거나 `lawd`를 직접 넣으면 된다.

등록 후 Actions 탭에서 "동네분석 데이터 자동 갱신"을 **Run workflow**로 즉시 한 번 실행해볼 수 있다.
로컬에서 돌릴 때는 `.env`에 키를 넣고 `python dongne/fetch_data.py --config dongne/targets.json`.
실행 로그에 시군구 단지별 최고가 TOP 15가 출력되므로 신축/재건축 단지 선정에도 참고할 수 있다.
데이터가 갱신되면 Pages 배포도 자동으로 이어서 실행된다 (`dongne-pages.yml`이 `dongne-auto.yml` 완료 이벤트를 받아 재배포).

### 자동화 커버리지

| 항목 | 자동화 | 방법 |
|---|---|---|
| 법정동코드(lawd) | ✅ | fetch_data.py / 앱 내 지역 선택 (행정표준코드_법정동코드 API) |
| 실거래 최고가·평당가 | ✅ | fetch_data.py / [정보 불러오기] (국토부 실거래가 API) |
| 전세가율 | ✅ | fetch_data.py / [정보 불러오기] (전월세 API, 순수 전세만 집계) |
| 상권 점포수 | ✅ | fetch_data.py / [정보 불러오기] (소상공인 상가정보 API) |
| 인구/20~40대 | ✅ (앱 내 [정보 불러오기]만) | 행정안전부_행정동별 성/연령별 주민등록 인구수 API — 시군구 단위로 조회해 행정동명으로 집계 (법정동↔행정동 코드 체계가 달라 정확한 행정동코드 대신 이름 매칭 사용) |
| 역 승하차 | ✅ (서울교통공사 노선만, 앱 내 [정보 불러오기]) | 서울교통공사_역별승하차인원 API — **최근 1주일 일별 데이터만 제공되어 365일 환산 추정치**. 코레일 구간 등 서울교통공사 관할이 아닌 역은 데이터 없음 |
| 입주 예정 | 수동 | 아실·부동산지인 입주물량 |
| 용적률 | 수동 | 네이버부동산 단지정보 / K-apt |
| 추진단계 | 수동 | 시·군·구청 고시공고 (전국 통합 API 없음) |

> 인구·역 승하차는 매월 배치(`fetch_data.py`)가 아니라 **앱의 [정보 불러오기] 버튼에서만** 동작한다 (배치는
> targets.json 기반 시군구 단위라 인구 API의 행정동 매칭 로직과 맞지 않음).
